# recon splat Jobs (office-map issue #5)

Files: `apps/recon.yaml` (PVC `recon-data` on talos-8me-tcy + `recon-files` pod), `apps/recon-scripts.yaml`
(GENERATED from the private office-map repo `recon/k8s/scripts/` by `recon/k8s/render-home-k8s.sh`),
`apps/recon-jobs.yaml` (GENERATED by `recon/k8s/gen_jobs.py`; one Job per run, re-run = new name).

## Workflow
1. Regenerate the files from office-map, commit only `apps/recon-*.yaml`, push, then poke Flux:
   `kubectl --context admin@home -n flux-system annotate --overwrite kustomization/apps reconcile.fluxcd.io/requestedAt="$(date +%s)"`
   (and the same on `gitrepository/flux-system`). If `apps` says "dependency infra is not ready", poke again a
   minute later — it was transient.
2. Watch: `kubectl --context admin@home get jobs -l app=recon`. Logs and results live on the PVC:
   `kubectl --context admin@home exec deploy/recon-files -- cat /data/runs/<run>/logs/job.log`,
   `.../metrics/quality.json`, `.../job.json`, `.../contact_sheet.jpg`.
3. GPU window: the 5090 is normally held by `inkling-2-mini-basalt`. The owner allows parking it
   (`replicas: 0` in `apps/inkling2-mini-basalt.yaml`) for recon runs; set it back to 1 afterwards. Never touch
   `pennyroyal-flashnext` (the RTX PRO 6000) without asking.

## Gotchas (each cost a failed Job)
- `kubectl` on the laptop needs `--context admin@home`: current-context is blank and the fallback auth points at
  a dead mock-oidc host.
- talos-8me-tcy has 8 CPUs / 32 GiB RAM: three Jobs requesting 3 CPUs each leave one Pending ("Insufficient
  cpu"); request 2 CPUs. nerfstudio splatfacto caches every train image in RAM while undistorting: OOMKilled at a
  12 Gi limit → use `--pipeline.datamanager.cache-images-type uint8` and a 20 Gi limit.
- HAMi `nvidia.com/gpumem` limits CUDA only. Brush (wgpu/Vulkan) is not metered, but the CUDA evaluator in the
  same Job is: 1000 MiB was too small for LPIPS-VGG; 6000 works.
- `pytorch/pytorch:2.7.1-cuda12.8-cudnn9-devel` supports sm_120 (5090). gsplat 1.5.3 JIT-compiles its CUDA
  extension on first import (~7 min on this node); keep `TORCH_EXTENSIONS_DIR` on the PVC, one dir per gsplat
  version (nerfstudio 1.1.5 pins gsplat 1.4.0 — separate dir).
- Shared venvs on the PVC: build under `flock`, and use `shopt -s inherit_errexit` — without it a failed pip
  install inside `$(...)` did not stop the script and the broken venv was marked `.ok`. PyPI read timeouts
  happen: `PIP_RETRIES=10 PIP_DEFAULT_TIMEOUT=120`.
- torch ≥ 2.6 loads checkpoints with `weights_only=True`; `ns-export` of nerfstudio 1.1.5 checkpoints fails on
  numpy scalars. Set `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1` for checkpoints the same Job wrote.
- The nvs-bench Tanks-and-Temples truck images are half resolution (979×546) but its COLMAP cameras are
  1957×1091. gsplat and Brush rescale silently; nerfstudio asserts. `prep_capture.py` rescales the cameras (and
  2D keypoints) to the real image size so every engine sees a self-consistent dataset.
- gsplat `rasterization(..., backgrounds=...)` in 1.5.3 rejects a `[1, 3]` tensor for a single camera; omit it
  (black is the default).
- Brush `RUST_LOG=info` writes megabytes of `load_scene_img` lines; use `warn`. Its progress bar is TTY-only.
- Keep `normalize_world_space` off (gsplat) and the identity dataparser transform (nerfstudio
  `--orientation-method none --center-method none --auto-scale-poses False
  --assume-colmap-world-coordinate-convention False`) so exported PLYs stay in COLMAP world coordinates for the
  common evaluator.
